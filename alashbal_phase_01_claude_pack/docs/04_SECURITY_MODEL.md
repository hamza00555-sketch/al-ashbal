# Security Model — الأشبال

## المبدأ

الأطفال + الفيديو + الأمنيات = أعلى حساسية في التطبيق.

## الأدوار

### child

يرى:

- ملفه.
- مهمته.
- تقدمه.
- أوسمته.
- أمنياته.
- حالة فيديوهاته.

لا يرى:

- بيانات أطفال آخرين.
- ملاحظات خاصة لغيره.
- لوحة المعلم.
- قرارات ولي الأمر الداخلية.

### parent

يرى:

- أطفاله المرتبطين به فقط.
- فيديوهات أطفاله قبل إرسالها للمعلم.
- ملخصات أطفاله.
- أمنيات أطفاله.

لا يرى:

- أطفال غير مرتبطين به.
- فيديوهات غير أبنائه.
- كل لوحة المعلم.

### teacher

يرى:

- الأطفال في حلقته فقط.
- الدروس والحضور.
- فيديوهات وصلت له بعد موافقة ولي الأمر.
- تقييمات الحلقة.

لا يرى:

- فيديو قبل موافقة ولي الأمر.
- أمنيات الطفل.
- تفاصيل عائلية غير لازمة.

### guest

يرى:

- عرض عام.
- إحصائيات جماعية.
- إنجازات غير حساسة.

لا يرى:

- أسماء كاملة إذا لم نقرر ذلك.
- فيديوهات.
- أمنيات.
- ملاحظات.
- تقييمات فردية.

### admin

يرى ويدير النظام، لكن يجب أن يكون استخدامه محدودًا.

## قواعد الفيديو

- الفيديو لا يصل للمعلم مباشرة.
- الفيديو يجب أن يدخل حالة `pending_parent_approval`.
- ولي الأمر فقط يوافق أو يطلب إعادة التسجيل.
- عند الموافقة فقط يصبح `pending_teacher_review`.
- يجب وجود سياسة حذف تلقائي لاحقًا.
- في Phase 01 نعرض flow فقط بدون رفع حقيقي.

## قواعد الأمنيات

- الأمنيات visible للطفل وولي الأمر فقط.
- المعلم لا يرى الأمنيات.
- الضيف لا يرى الأمنيات.
- الأمنيات ليست وعدًا ماديًا.

## قواعد ضيف الشرف

لا تعرض أي شيء قد يحرج الطفل أو يكشف خصوصيته.

## أخطاء ممنوعة

- أي page تعرض كل الأطفال بدون فلترة دور المستخدم.
- أي component يستخدم mock data عامة بدون توضيح role scope.
- أي video card يظهر في teacher dashboard قبل `parentApproved`.
- أي wish card يظهر خارج parent/child context.
