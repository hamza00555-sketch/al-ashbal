# قائمة اختبار الجوال — Mobile QA Checklist

> ملف توثيق فقط. لا يغيّر التطبيق ولا UI ولا CSS ولا منطقًا ولا بيانات.
> الغرض: اختبار يدوي على جهاز جوال حقيقي لمسار التسجيل الكامل، لأن Playwright
> لا يستطيع اختبار الكاميرا/الميكروفون الحقيقيين.

**المسار المُختبَر:** تسجيل الطفل → موافقة ولي الأمر → مراجعة المعلم → رجوع للطفل.

**نقطة التثبيت وقت كتابة هذه الخطة:** commit `f283ff3` (راجع `docs/CURRENT_MVP_CHECKPOINT.md`).

---

## قبل البدء (تجهيز)

- [ ] افتح رابط Vercel للتطبيق على الجهاز (iPhone Safari و/أو Android Chrome).
- [ ] استخدم اتصال إنترنت مستقر.
- [ ] التطبيق حاليًا **بيانات demo/localStorage** — البيانات محلية على نفس المتصفح؛ لا تبدّل بين متصفحات أو أجهزة وتتوقع استمرار نفس الحالة.
- [ ] ملاحظة خصوصية: الفيديو لا يصل للمعلم إلا **بعد موافقة ولي الأمر** — تحقّق من احترام هذا التسلسل.
- [ ] (اختياري) سجّل فيديو شاشة للجهاز أثناء الاختبار لتوثيق أي مشكلة.

---

## 1. فتح التطبيق على الجوال

- [ ] الصفحة الرئيسية للطفل `/child` تفتح بدون انكسار.
- [ ] لا توجد عناصر خارج الشاشة أو نصوص مقطوعة (RTL سليم).
- [ ] **الشريط السفلي (bottom nav)** يظهر ويعمل: الرئيسية / الدروس / مهامي / تقدّمي / أمنياتي.
- [ ] الشريط السفلي **ثابت** ولا "يقفز" عند التمرير لأعلى/أسفل.
- [ ] النصوص واضحة ومقروءة، والأيقونات بحجم مناسب للمس.
- [ ] جرّب نفس الفحص لصفحات: `/parent` و `/teacher`.

## 2. اختبار صلاحيات التسجيل (`/child/tasks`)

- [ ] قسم **«تحتاج إنجاز»** يظهر أعلى الصفحة (active-first).
- [ ] افتح مهمة من نوع **تسميع** (recitation).
- [ ] اضغط زر **«ابدأ التسجيل»**.
- [ ] يطلب المتصفح **إذن الميكروفون/الكاميرا**.
- [ ] وافق على الصلاحيات.
- [ ] التسجيل **يبدأ فعليًا** (مؤشر تسجيل/زمن يعمل).
- [ ] جرّب الحالتين إن أمكن: تسجيل **صوت** وتسجيل **فيديو**.
- [ ] إن رفضت الصلاحية: تأكد أن التطبيق يعرض رسالة مفهومة ولا ينكسر.

## 3. اختبار المعاينة

- [ ] أوقف التسجيل.
- [ ] شغّل **المعاينة**.
- [ ] الصوت/الفيديو **يُعرض/يُسمع** بشكل صحيح.
- [ ] زر **الإرسال** واضح وقابل للضغط.
- [ ] (إن وُجد) زر **إعادة التسجيل** يعمل ويعيد البدء.

## 4. اختبار الإرسال

- [ ] اضغط **إرسال** التسجيل.
- [ ] حالة المهمة **تتغيّر** عند الطفل (مثلاً: بانتظار موافقة ولي الأمر / تم الإرسال).
- [ ] المهمة **تنتقل** من قسم «تحتاج إنجاز» إلى قسم **«تم إرسالها أو إنجازها»**.
- [ ] لا تظهر المهمة مكررة في القسمين.

## 5. اختبار ولي الأمر (`/parent/approvals`)

- [ ] التسجيل الجديد يظهر في **قسم المعلّق (بانتظار الموافقة)** أعلى الصفحة.
- [ ] تظهر بيانات الطفل الصحيحة (الاسم/الأفاتار) وعنوان التسميع.
- [ ] اضغط **«موافقة»**.
- [ ] يظهر تأكيد أن التسجيل **انتقل للمعلم**.
- [ ] (تحقق سلبي) قبل الموافقة: تأكد أن العنصر **لم يصل** لصفحة المعلم.
- [ ] جرّب أيضًا **«إعادة التسجيل»** على عنصر آخر وتأكد أن الطفل يُخطر.

## 6. اختبار المعلم (`/teacher/reviews`)

- [ ] قسم **«بانتظار المراجعة»** يظهر أولًا.
- [ ] التسجيل الجديد (المعتمد من ولي الأمر) يظهر **أعلى** قائمة المعلّق (الأحدث أولًا).
- [ ] لا يظهر التسجيل الجديد **تحت** عناصر سبق قبولها.
- [ ] شغّل **المعاينة**.
- [ ] اضغط **«قبول التسميع»**.
- [ ] العنصر **ينتقل** إلى قسم **«تمت مراجعتها»** وتظهر شارة القبول.
- [ ] (اختياري) جرّب **«طلب إعادة التسميع»** و**«إضافة ملاحظة»** على عنصر آخر.

## 7. الرجوع للطفل (`/child/tasks` و `/child/progress`)

- [ ] في `/child/tasks`: الحالة النهائية للمهمة تظهر بشكل صحيح (مقبول/يحتاج إعادة).
- [ ] قوائم **active-first** ما زالت صحيحة (لا تنكسر بعد التحديث).
- [ ] في `/child/progress`: حلقات التقدّم تظهر بشكل سليم.
- [ ] كرت **«نقاطي»** والأيقونة الكبيرة تظهر بدون انكسار.
- [ ] كرت **«أوسمتي»**: الأوسمة وأسماؤها تظهر، والـ watermark خفيف غير مزعج.
- [ ] لا أخطاء في console (إن أمكن الفحص عبر remote debugging).

---

## ملاحظات بيئة الاختبار

- البيانات محلية (localStorage/IndexedDB) — إعادة تحميل نفس المتصفح تحافظ على الحالة؛ مسح بيانات الموقع يصفّر التجربة.
- الإشعارات حاليًا **ليست push حقيقية** — هي إشعارات داخل التطبيق فقط.
- التقاط الكاميرا/الميكروفون يحتاج **HTTPS** (رابط Vercel يوفّره) وإذن المستخدم.
- على iOS Safari قد يتطلب تشغيل الصوت/الفيديو **تفاعل المستخدم** (نقرة) — هذا سلوك متصفح طبيعي.
