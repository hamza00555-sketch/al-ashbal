## ما جرى التحقق منه آليًا (محاكاة إنتاجية كاملة — 31/31 ✅)

بيئة القياس: بناء إنتاجي + متصفح جوال (390×844) + Supabase وهمي حالتي
كامل (auth + REST + Storage الموقّع) — نفس مسارات الكود التي ستضرب
الإنتاج حرفيًا:

1. المعلمة أنشأت مهمة «سورة الفاتحة» (10 نقاط) ودعوة عائلة. ✅
2. جهاز عائلة جديد سجّل ولي أمر وطفلين. ✅
3. الطفل الأول سجّل صوتًا فعليًا (ميكروفون) ← رفع عبر رابط موقّع ← صف
   تسليم `pending_parent` بمسار خادمي خاص بالطفل. ✅
4. التكرار لنفس المهمة مرفوض، والشقيقة أنشأت تسليمها المستقل (لا دهس). ✅
5. الوليّ رأى الاثنين، شغّل الصوت برابط موقّع (token)، ووافق ← `pending_teacher`. ✅
6. المعلمة (جهاز آخر) رأت الاثنين: قبلت الأول (10 نقاط ← ledger للطفل
   الصحيح فقط) وطلبت إعادة للثانية. ✅
7. الوليّ رأى النتيجة بعد التحديث (النقاط + الحالات)، والطفلة رأت «مطلوب
   إعادة» وأعادت الإرسال (تحديث نفس الصف) ← `pending_parent` مجددًا. ✅
8. توكن منحة معبوث به ← رفض خادمي، لا صف ولا ملف. ✅

## سيناريو البايلوت الحقيقي (يُنفَّذ على al-ashbal.vercel.app)

> ينفذه المالك مع أسماء وعائلة واحدة حقيقية — علّم كل بند:

- [ ] 1. أسماء تدخل ← «مراجعة التسميع» ← تنشئ مهمة (مثال: سورة الفاتحة، 10).
- [ ] 2. أسماء تنشئ دعوة عائلة من «الدعوات» وترسل الرابط واتساب.
- [ ] 3. ولي الأمر يفتح الرابط على جواله، ينشئ حسابه ويسجل طفلًا أو اثنين.
- [ ] 4. لوحة ولي الأمر تظهر الأطفال. مبدّل الأطفال يعمل على جهازه.
- [ ] 5. الطفل من «مهامي» ← «تسميعي للمعلمة» يسجّل ويرسل.
- [ ] 6. ولي الأمر يرى «بانتظار موافقتك»، يستمع، ويوافق.
- [ ] 7. أسماء ترى التسميع في «تسميعات قاعدة البيانات»، تستمع، وتقبل بالنقاط.
- [ ] 8. ولي الأمر يحدّث الصفحة: «مقبول 🎉» والنقاط ظاهرة على الطفل.
- [ ] 9. أعد فتح الصفحات بعد إغلاق المتصفح: كل شيء باقٍ (قاعدة بيانات).
- [ ] 10. جرّب «طلب إعادة» مرة واحدة وتأكد أن الطفل يستطيع إعادة الإرسال.

إن تعثّر أي بند: انسخ الرسالة الظاهرة حرفيًا وأبلغني.
