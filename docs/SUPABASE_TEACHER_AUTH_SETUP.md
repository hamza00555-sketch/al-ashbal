# مصادقة المعلم الحقيقية — Supabase Auth (المرحلة 2)

هذه الوثيقة تشرح تفعيل دخول المعلم الحقيقي (بريد إلكتروني + كلمة مرور عبر
Supabase Auth) بعد إيقاف بوابة الأكواد المحلية التجريبية (TCH-001/TCH-002).

**المبدأ:** لا يوجد تسجيل عام للمعلمين. حساب المعلم يُنشأ فقط بسكربت
`scripts/bootstrap-teacher.mjs` بيد مالك المشروع.

---

## 1) كيف تعمل الحماية الآن

| الطبقة | الملف | الدور |
| --- | --- | --- |
| Proxy (خادم) | `src/proxy.ts` | يعمل قبل أي صفحة `/teacher/*`: يجدّد جلسة Supabase، ويعيد الزائر غير المسجّل إلى `/teacher/login`، ويعيد المسجّل بعيدًا عن صفحة الدخول. HTML لوحة المعلم لا يصل أبدًا لغير المسجّل. |
| Layout (خادم) | `src/app/teacher/layout.tsx` | يقرأ بروفايل المستخدم تحت RLS ويتحقق من دور `teacher`. مستخدم مسجّل بدور آخر (وليّ أمر مثلًا) يرى شاشة «هذا الحساب ليس حساب معلم» مع زر خروج — لا بيانات معلم. |
| Data access (خادم) | `src/lib/backend/auth.ts` | `getCurrentUserProfile` / `getCurrentTeacherProfile` / `requireTeacher` — القراءة من `profiles` + `teacher_profiles` عبر RLS (`id = auth.uid()`)، والدور يُقرأ من الخادم فقط، لا من العميل أبدًا. |
| Login (متصفح) | `src/app/teacher/login/` | `signInWithPassword`؛ الجلسة تُخزَّن في كوكيز (`@supabase/ssr`) فيراها الخادم. |

**البوابة التجريبية القديمة أُزيلت بالكامل**: حُذف `src/lib/demo/teacherSession.ts`
(أكواد TCH-001/TCH-002)، ولا يقرأ أي كود المفتاح
`alashbal:demo-active-teacher-session` — قيمة قديمة في localStorage لا تمنح أي
صلاحية، بل تُمسح تلقائيًا عند فتح صفحة الدخول وعند الخروج.

## 2) إنشاء أول حساب معلم (Bootstrap)

يُنفَّذ على جهازك (يحتاج وصولًا مباشرًا إلى `*.supabase.co`):

```bash
# داخل مجلد المشروع، مع .env.local مكتمل (URL + المفاتيح):
TEACHER_EMAIL="teacher@example.com" \
TEACHER_PASSWORD="كلمة-مرور-قوية" \
TEACHER_DISPLAY_NAME="الأستاذ خالد" \
npm run bootstrap:teacher
```

- يمكن وضع المتغيرات الثلاثة مؤقتًا داخل `.env.local` بدل السطر الطويل —
  **احذف `TEACHER_PASSWORD` بعد نجاح التشغيل**.
- السكربت **idempotent**: إعادة تشغيله آمنة؛ حساب موجود يُعاد استخدامه
  **دون تغيير كلمة مروره**.
- ما يفعله: إنشاء مستخدم Auth (بريد مؤكَّد) → `profiles` بدور `teacher` →
  `teacher_profiles` → ربطه بالحلقة الافتراضية في `class_teachers`
  (أقدم حلقة نشطة، أو `TEACHER_CLASS_ID` إن حُدِّد).
- يستخدم مفتاح الخدمة (server-only) لأن `class_teachers` بلا سياسة إدخال
  للعملاء — بالتصميم. السكربت لا يطبع أي مفتاح أو كلمة مرور.

## 3) الدخول والخروج

- **الدخول:** `/teacher/login` — البريد الإلكتروني + كلمة المرور ثم «دخول».
  خطأ البيانات يعرض «بيانات الدخول غير صحيحة»؛ مشكلة الشبكة تعرض رسالة اتصال
  مختلفة (حتى لا يظن المعلم أن كلمة مروره خاطئة).
- **الخروج:** زر «تسجيل خروج» في شريط «مسجل كمعلم» (أو في شاشة رفض الوصول):
  `supabase.auth.signOut()` + مسح مفتاح الجلسة التجريبية القديمة + العودة
  لصفحة الدخول.
- **نسيت كلمة المرور؟** لا يوجد استرجاع ذاتي في هذه المرحلة — يعيد المالك ضبطها
  من لوحة Supabase (Authentication → Users → Reset password).

## 4) حدود معروفة (مقصودة في هذه المرحلة)

- **بقية التطبيق ما زال localStorage**: الدعوات، الأطفال، أولياء الأمور،
  التسليمات، التسجيلات، النقاط — لم يُرحَّل منها شيء بعد. هوية المعلم فقط حقيقية.
- الدعوات التجريبية المنشأة سابقًا كانت مفهرسة بمعرّف المعلم التجريبي
  (`teacher-001`) — لن تظهر في قائمة معلم حقيقي (لكن روابطها عبر `/join` تعمل).
  الدعوات الجديدة تُفهرس بمعرّف المعلم الحقيقي.
- بيئة التطوير السحابية لهذه الجلسات **تحجب** الاتصال المباشر بـ
  `*.supabase.co`: داخلها يعمل التحقق من التحويلات والبوابة، أما الدخول الفعلي
  بالحساب و`bootstrap:teacher` و`verify:supabase` فتُنفَّذ على جهازك.
- **قبل مستخدمين حقيقيين:** دوّر مفتاح الخدمة (sb_secret) لأنه مرّ في المحادثة
  أثناء الإعداد — التدوير خارج نطاق هذه المهمة عمدًا. وبوابة الأمان النهائية
  (Security Launch Gate) ما زالت مطلوبة قبل أي إطلاق عام.

## 5) استكشاف الأخطاء

| العرض | السبب الأرجح |
| --- | --- |
| «بيانات الدخول غير صحيحة» | بريد/كلمة مرور خاطئة (400 من Supabase). |
| «تعذّر الاتصال بالخادم» | لا وصول إلى supabase.co (شبكة/جدار ناري) أو مشروع موقوف. |
| «هذا الحساب ليس حساب معلم» | المستخدم مسجّل لكن `profiles.role ≠ teacher` أو لا صف له — شغّل السكربت لهذا البريد. |
| حلقة تحويل إلى /teacher/login رغم دخول ناجح | الكوكيز محجوبة في المتصفح، أو `NEXT_PUBLIC_SUPABASE_*` غير مضبوطة على بيئة النشر. |
